# SFTF: Spatial-Temporal Fingerprint Fusion for Fake News Detection on Weibo

**SFTF: Fake News Detection with Spatial Fingerprint Meta-Path and Temporal Fingerprint Meta-Trend based on Temporal Multi-Level Comment Dataset** is a spatial-temporal fingerprint fusion framework for fake news detection on social media. It jointly models news propagation structures, changes in sentiment during the propagation process, and the semantic content of news articles. Real and fake news are distinguished through a distance-based decision mechanism in a manifold metric space.

---

## 1. Overview

News propagation on social media involves more than the news text itself. It also includes comments and replies posted by users, as well as interactions that evolve over time. Relying solely on textual content may fail to fully capture the information embedded in propagation structures and their temporal dynamics.

SFTF models the news propagation process through three complementary types of fingerprints:

1. **Spatial Fingerprint:** Uses the hierarchical propagation structure formed by news posts, first-level comments, and second-level replies, together with node-level sentiment categories, to construct sentiment-aware meta-paths.
2. **Temporal Fingerprint:** Maps propagation events associated with different sentiment meta-paths into time series, extracts frequency-domain meta-trends through the Discrete Fourier Transform (DFT), and aggregates them using multi-head attention.
3. **Semantic Fingerprint:** Uses BERT to extract semantic representations of news content, complementing the structural and temporal information.

The model then fuses these representations and maps the fused representation into a manifold metric space. Classification is performed using the Euclidean distance between a sample and the manifold center, together with a decision threshold.

### 1.1 Research Task

SFTF addresses a news-level binary classification task, assigning each news item to one of two categories: **Real** or **Fake**. The model uses news text and structural, temporal, and sentiment information from the associated propagation process to make its prediction.

### 1.2 Main Components

- News and comment data preprocessing;
- Multi-level sentiment annotation;
- Sentiment-aware meta-path construction;
- BERT-based semantic feature extraction;
- Spatiotemporal fingerprint encoding and fusion;
- Manifold metric learning and threshold-based classification;
- Main-dataset training, external-dataset evaluation, and experimental analysis.

## 2. Methodology

### 2.1 Spatial Fingerprint: Sentiment-Aware Meta-Paths

SFTF organizes news items and their propagation nodes into a three-level structure:

- **N:** News node;
- **U / C1:** First-level comment node;
- **V / C2:** Second-level reply node.

Each node is represented using a three-class sentiment label:

- `0`: positive;
- `1`: neutral;
- `2`: negative.

Based on the sentiment combinations of news nodes, first-level comments, and second-level replies, the framework constructs:

- 9 NU sentiment meta-paths;
- 27 NUV sentiment meta-paths;
- **36 sentiment channels** in total.

Meta-paths are stored as text files, with each line representing one propagation path. Path fields are separated by `——` (U+2014 U+2014). The specific encoding is generated by the implementation in `model/metapath_construction/`.

### 2.2 Temporal Fingerprint: Frequency-Domain Meta-Trends

SFTF constructs propagation time series using the relative timestamps recorded in the meta-paths, and extracts frequency-domain information through DFT / rFFT. The main configuration in the training code is as follows:

| Parameter                                    | Main Training Script |
| -------------------------------------------- | -------------------: |
| Number of sentiment channels                 |                   36 |
| Number of temporal bins                      |                  100 |
| Maximum time range                           |      172,800 seconds |
| Number of selected frequency coefficients, K |                   12 |
| Temporal branch embedding dimension          |                   64 |
| Number of attention heads                    |                    4 |

These settings correspond to `model/training_evaluation/train_deepseek.py`.

### 2.3 Semantic Fingerprint: BERT Representations

SFTF uses BERT to represent the semantic content of news articles. The BERT feature files contain 768-dimensional floating-point vectors, with one feature vector corresponding to each news item.

### 2.4 Fusion and Manifold-Based Classification

The model fuses the spatiotemporal representations with BERT-based semantic representations. It then computes the Euclidean distance between each sample embedding and the manifold center in the manifold metric space, and uses a decision threshold to classify the sample as real or fake.

The main parameters in the training script include:

| Parameter                           |  Value |
| ----------------------------------- | -----: |
| BERT semantic dimension             |    768 |
| Temporal branch embedding dimension |     64 |
| Metric-space dimension              |    128 |
| Batch size                          |     32 |
| Learning rate                       | 0.0003 |
| Epochs                              |    100 |
| Random seed                         |      8 |
| β                                   |    0.5 |
| δ                                   |    2.0 |
| η                                   |    1.0 |
| BERT weighting coefficient          |    0.2 |

## 4. Weibo-25 Dataset Description

Weibo-25 is the Weibo news dataset used in this project. It contains real and fake news items, together with propagation interactions associated with the news. The dataset is divided as follows:

| Category  |  Training | Validation |    Test |     Total |
| --------- | --------: | ---------: | ------: | --------: |
| Real      |     3,562 |      1,018 |     508 |     5,088 |
| Fake      |     3,129 |        894 |     447 |     4,470 |
| **Total** | **6,691** |  **1,912** | **955** | **9,558** |

The split approximately follows a 70% / 20% / 10% training, validation, and test ratio.

### 4.1 Data Directories

The following data categories are organized under `model/data/`:

| Subdirectory      | Contents                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| `raw_data/`       | Real / Fake news tables and comment tables                                                     |
| `splits_data/`    | Training, validation, and test split files                                                     |
| `sentiment_data/` | L0 news-level, L1 first-level-comment-level, and L2 second-level-reply-level sentiment results |
| `metapath_data/`  | Node-encoding tables and merged or split sentiment meta-paths                                  |
| `bert_feature/`   | 768-dimensional BERT feature arrays                                                            |

The main meta-path files contain the following numbers of lines:

- `Deepseek_real_metapaths.txt`: 314,585 lines;
- `Deepseek_fake_metapaths.txt`: 110,159 lines.

Each line represents either a path containing a first-level comment or a path containing a first-level comment and a second-level reply.

### 4.2 Fields in the De-identified Data

The files `raw_data/{real,fake}_news.xlsx` contain the following fields:

```text
id, post_url, news_id, post_time, comment_count,
like_count, repost_count, image_url, video_url, repost_url
```

The files `raw_data/{real,fake}_comments.xlsx` contain the following fields:

```text
news_id, post_url, post_time, image_url, video_url,
repost_url, repost_count, comment_count, like_count,
comment_author_url, comment_time, comment_likes,
reply_time, reply_author_url
```

The files `splits_data/{real,fake}_{train,val,test}.csv` contain:

```text
id, post_url
```

The de-identified data does not contain the following text or author fields:

```text
news_content
comment_content
reply_content
comment_author
reply_author
```

## 5. Data Privacy and Availability

### 5.1 Why Are the Full News, Comment, and Reply Texts Not Released?

To protect the privacy of social-media users, the de-identified data does not include the full text of news posts, first-level comments, or second-level replies, nor user nicknames or author names. These fields have been removed from the de-identified tables.

Accordingly:

- This repository should not be understood as containing the complete original Weibo-25 news and comment texts.
- The data tables primarily retain structured timestamps, interaction statistics, pseudonymized linkage identifiers, and derived information that has already been generated.
- Researchers who need to execute steps that depend on original text or author fields must independently prepare the corresponding data.

### 5.2 Pseudonymization

The de-identification procedures include the following:

| Original Information            | Processing                                                |
| ------------------------------- | --------------------------------------------------------- |
| News URLs                       | Replaced with pseudonymous identifiers derived using HMAC |
| User-related URLs               | Replaced with pseudonymous identifiers derived using HMAC |
| Repost URLs                     | Replaced with pseudonymous identifiers                    |
| News IDs                        | Replaced with pseudonymous identifiers                    |
| Image and video URLs            | Replaced with `[MEDIA_URL]`                               |
| News, comment, and reply text   | Removed                                                   |
| User nicknames and author names | Removed                                                   |

The HMAC-based processing constitutes **pseudonymization**, not irreversible anonymization.

The HMAC secret key is not included in the public files. Secret keys, cookies, API keys, and other authentication credentials must never be committed to the public repository.

The same HMAC-SHA256 pseudonymization scheme is also applied to the external evaluation datasets under `external_evaluation/PHEME/` and `external_evaluation/Twitter-COVID19/`: node and author identifiers are replaced with `POST_ID_` / `AUTHOR_` hashes, media URLs are replaced with `[MEDIA_URL]`, and the original tweet text, author names, and author/original/repost URLs are removed. The pseudonymization key is likewise internal-only and never distributed.

### 5.3 Data Availability and Independent Collection

The project provides Weibo data-collection and data-organization scripts in `Data_Crawling/`. These scripts are provided as technical references for researchers who have lawful access to the platform and comply with its applicable rules.

The relevant scripts involve Selenium-based login, Weibo cookies, or API-access configuration. The data that can actually be retrieved depends on:

- The researcher's Weibo account and platform access;
- Whether the posts, comments, and replies remain accessible;
- Changes to platform APIs and page structures;
- Whether historical content is still available;

The crawling scripts provide technical workflows only. They do not guarantee that all historical news posts, comments, or replies can be retrieved.

> **The datasets are not distributed in this repository.** See [`external_evaluation/README.md`](external_evaluation/README.md) for the data sources and the steps to obtain and rebuild the derived data.

```bash
cd external_evaluation/PHEME
```

**BERT feature extraction:**

```bash
python pheme_bert.py
```


```text

├── pheme_best.pth
└── pheme_threshold.json
```
